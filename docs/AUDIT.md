# ET1CRUEL — Design Audit (Artist Portfolio lens)
**วันที่ตรวจ:** 2026-10-08 · **ไฟล์หลัก:** `index.html` (1317 บรรทัด) · **วิธีตรวจ:** อ่านโค้ดจริงทั้งหมด (HTML + inline CSS ~240 บรรทัด + `css/*.css` + JS 7 ไฟล์) — ไม่ได้เปิดเบราว์เซอร์จริง (ไม่มีเครื่องมือ render ในสภาพแวดล้อมนี้)
**เลนส์แบรนด์:** ดิบ เท่ มืด ลึกลับ แบบศิลปิน — ไม่ใช่เว็บขายของ

## 1. ปัญหา Visual Hierarchy, Typography, Color, Spacing

### Hierarchy — ทุกอย่างตะโกนพร้อมกัน
- **Hero ทำงาน 3 อย่างในจอเดียว:** คำประกาศตัวตน + KPI 4 การ์ด (CLEAR/ACTIVE/GOLD/PARTY) + สูตรเงิน + วิธีใช้เว็บ — คนเข้าใหม่ไม่รู้ว่านี่คือ **ศิลปิน** หรือแดชบอร์ดเกม
- **Treasury (เงิน) อยู่เหนือทุกอย่าง** — เปิดเว็บมาเจอตัวเลขบัญชี 3 คอลัมน์ก่อนผลงานเพลง สำหรับแบรนด์ศิลปินควรเป็นดนตรี/ตัวตนขึ้นก่อน เงินอยู่ลึกกว่านี้
- **Section 19 ใบหน้าตาเหมือนกันหมด** (icon + h2 + ป้าย count) — สมองแยกไม่ออกว่าอันไหนคือ "ผลงาน" อันไหนคือ "ตารางข้อมูล" (ระบบพับ section ช่วยไว้แล้ว แต่หัวข้อเท่ากันหมด)
- ไม่มีผลงานเด่น (featured track / อัลบั้ม / เพลงล่าสุด) บนหน้าแรกเลย — บีท 22 เพลงซ่อนอยู่คนละหน้า (`beat-select.html`)

### Typography — 4 ฟอนต์แย่งกันพูด
- ใช้ **4 ตระกูล**: Chakra Petch + IBM Plex Sans Thai + Noto Serif Thai + Press Start 2P — เยอะไปสำหรับเว็บหน้าเดียว
- **Press Start 2P ไม่มี glyphs ภาษาไทย** เอาไปทำป้ายจิ๋ว (eyebrow, lv, count, nav) → ไทยตกไปใช้ฟอนต์สำรอง เกิดเป็น texture ผสม 2 ฟอนต์ในบรรทัดเดียว ดูไม่เนี้ยบ
- Noto Serif Thai โผล่แค่คำเดียวใน h1 (`span`) — จ่ายค่าน้ำหนักฟอนต์โดยได้ใช้นิดเดียว
- ข้อดีที่ต้องเก็บ: body 19px + line-height 2.05 อ่านไทยสบาย, มี `display=swap`, เคารพ `prefers-reduced-motion`

### Color — ชื่อ gold แต่ได้เขียวสนามกอล์ฟ
- `--gold: #4ADE80` กับ `--xp: #3DFF88` คือ**เขียวเดียวกันเกือบ 100%** ตั้งชื่อคนละอย่างแต่ตาแยกไม่ออก
- นับ accent ที่แข่งกัน: เขียว×2, แดง HP, น้ำเงิน MP, amber, pink, indigo, cyan, violet + ชิปหุ้นเขียว/แดง — **~10 สี** โทนรวมเลยออก "ตู้เกมอาร์เคด" ไม่ใช่ "ศิลปินลึกลับ"
- Glow ฟุ้งทุกจุด (text-shadow 18–24px, box-shadow เรืองแสงบนปุ่ม/บาร์/badge) — ของที่เรืองแสงทุกชิ้น = ไม่มีชิ้นไหนเด่น
- สีพอ violence น้อยจุดที่ทำถูก: ป้ายแดงเฉพาะขาดทุน/ลบ, เหลืองเฉพาะเควสค้าง — เก็บไว้

### Spacing — โครงดี แต่ชั้นเยอะ
- gap 22px + card padding 32px สม่ำเสมอ ถือว่าดี
- ปัญหาคือ**ชั้นลอยทับกัน**: topbar sticky + qtracker fixed + treeFab + stockFab + bottomnav (mobile) = 5 layer ลอยพร้อมกันบนจอเล็ก

## 2. ปัญหา Responsive และ Performance

### Responsive
- มี breakpoint ครบ (520/680/700/900/1100/1200/1280/1600) — โครงไม่พัง
- **nav 19 ลิงก์กลายเป็นแถบเลื่อนแนวนอนบนมือถือ** (`display:flex; overflow:auto`) — ใช้งานจริงยาก ไม่มี grouping ช่วย
- มือถือซ่อน `hudbars` (HP/MP/EXP) ทิ้ง — เกจที่เป็นเอกลักษณ์ RPG หายไปเฉยๆ
- ตารางหุ้น `min-width:620px` ต้องเลื่อนข้าง — รับได้ แต่คอลัมน์ 8 ช่องบนจอ 360px คือสไลด์ยาว
- ปุ่ม collapse 44px ✓, ปุ่มส่งแชท 44px ✓ — touch target ผ่าน

### Performance
- **three.js ผ่าน CDN (~600KB, defer) + galaxy 650 particles + rAF loop ตลอดเวลา** — มี fallback ถ้า CDN ตายก็จริง แต่บนมือถือสเปกต่ำคือสูบแบต/GPU ตั้งแต่เปิดหน้า
- **อนิเมชันวนลูปไม่หยุด**: blink, slide, questGlow, floaty h1, เหรียญลอย 10 ตัว — งามแต่ไม่มีปุ่มปิดรวม (มีแค่ respect reduced-motion)
- ฟอนต์ 4 ตระกูลหลายน้ำหนัก = render-blocking ช่วงแรก (โชคดีมี display=swap)
- Third-party chain: TradingView widgets (lazy ผ่าน IntersectionObserver ✓ดี), Finnhub/CoinGecko/ER-API, favicon ผ่าน `google.com/s2` รายแถวใน port.js — ถ้าเน็ตช้า ตารางหุ้นจะโหรงเหรงโดยไม่มี skeleton
- `backdrop-filter: blur(14px)` บนพื้นผิวใหญ่หลายใบ + `will-change:transform` บน hero/treasury/cards — ตัวกิน GPU บนมือถือ

## 3. คะแนนความสวยงาม: **6.5 / 10**

| ด้าน | คะแนน | เหตุผล |
|---|---|---|
| เอกลักษณ์/ธีม | 8 | RPG + ไทย + เขียวมิสต์ชัด จำได้ ไม่โหล |
| ฟังก์ชัน/ข้อมูลจริง | 8 | ระบบเยอะและใช้ได้จริง (พอร์ต, แชทหุ้น, vault, เควส) |
| Hierarchy | 5 | ทุกอย่างตะโกนพร้อมกัน, เงินนำหน้าเพลง |
| Color discipline | 5 | 10 accent แข่งกัน, เขียวซ้ำชื่อคนละอย่าง |
| Typography | 6 | อ่านง่ายแต่ฟอนต์ 4 ตระกูล + pixel font กับไทยไม่เข้ากัน |
| Mobile | 6 | ไม่พังแต่ nav แถบยาว + เสีย HUD + layer ลอยชนกัน |
| Performance | 6 | lazy ดีบางจุด แต่ galaxy + loop animation + blur หนักมือถือ |

**สรุปประโยคเดียว:** โครงและระบบแข็งแรงระดับ 8 แต่ art direction ยังเป็น "แดชบอร์ดเกมเรืองแสง" ไม่ใช่ "ศิลปินดิบลึกลับ" — ช่องว่าง 3.5 แต้มอยู่ที่ดีไซน์ ไม่ใช่โค้ด

## 4. สิ่งที่ต้องแก้ 5 อันดับแรก (ห้ามแต่งข้อมูล ห้ามลบฟังก์ชัน)

### #1 — สลับลำดับ Hero: ศิลปินก่อน ตัวเลขทีหลัง
- **ทำ:** hero ขึ้นด้วย statement + ผลงานเด่น 1 ชิ้น (เพลง/บีทล่าสุด + ปุ่มฟัง) ย้าย KPI เงิน (GOLD) ลงไปรวมกับ Treasury, Treasury ยุบเหลือสรุปบรรทัดเดียว + กางดูเต็มได้
- **ห้าม:** เปลี่ยนตัวเลข/ลบ section
- **ได้:** เข้าหน้าแล้วรู้ทันทีว่า "นี่คือศิลปิน" ตรงโจทย์แบรนด์

### #2 — ลดพาเลตต์ 10 สี → 3 สี + กฎ glow
- **ทำ:** เกรดมิสต์เขียว 1 เฉด (ลบ `--xp` ซ้ำซ้อน), ขาวกระดูก, แดง/เหลืองเก็บไว้เฉพาะ "ลบ/ขาดทุน" และ "เควสค้าง" เท่านั้น · glow เหลือเฉพาะสถานะสำคัญ (HP วิกฤต, เป้าหมาย 1M)
- **ห้าม:** เปลี่ยนความหมายสี (เขียว=ดี/เงิน แดง=ลบ เหลือง=ค้าง)
- **ได้:** มืดลึกลับขึ้นทันทีโดยไม่ต้องรีดีไซน์

### #3 — ฟอนต์เหลือ 2 ตระกูล + เลิก pixel font กับภาษาไทย
- **ทำ:** เก็บ IBM Plex Sans Thai (เนื้อความ) + Chakra Petch (ตัวเลข/ป้ายอังกฤษ) · เอา Press Start 2P ออกจากป้ายที่มีไทยปน · Noto Serif ใช้ต่อเฉพาะ h1 หรือถอดออก
- **ได้:** โหลดเร็วขึ้น + ป้ายไทยเนี้ยบสม่ำเสมอ

### #4 — Mobile nav + floating layers
- **ทำ:** nav มือถือจัดกลุ่มพับได้ (4 กลุ่มเดิมมีแล้ว เอามาใช้) แทนแถบเลื่อนยาว 19 ลิงก์ · คืน HUD แบบย่อ (เงินรวม+เควสค้าง) แทน hudbars ที่ซ่อนไป · กัน qtracker/treeFab/stockFab ชนกันที่มุมขวาล่าง
- **ได้:** มือถือใช้งานได้จริง ไม่ใช่แค่ไม่พัง

### #5 — งบ Performance: ปิดของหนักบนมือถือ
- **ทำ:** three.js galaxy + เหรียญลอย รันเฉพาะจอใหญ่ + ไม่ใช่ reduced-motion · ลด blur 14px → 8px บนมือถือ · ตารางหุ้นใส่ skeleton ตอนโหลดแทนช่องว่าง
- **ห้าม:** ลบฟังก์ชัน/เอฟเฟกต์บน desktop
- **ได้:** เปิดหน้าไว สูบแบตน้อยลง ความรู้สึก "ลื่น" ขึ้น

## 6. ข้อจำกัดที่ต้องพูดตรงๆ
- ตรวจด้วยการอ่านโค้ดเท่านั้น **ไม่ได้เปิดเบราว์เซอร์จริง** (ไม่มีเครื่องมือ render) — contrast ตัวเลข, จังหวะ animation, สัมผัสมือถือจริง ยังไม่ได้เทสต์ ต้องเช็คบนเครื่องจริงก่อนสรุป
- ตัวเลขทุกอย่าง (58 QUESTS, 96,500 ฿, 25,143 ฯลฯ) เป็นของเดิมในโค้ด — audit นี้ไม่ยืนยันความถูกต้องของข้อมูล แค่ยืนยันว่าไม่แตะต้อง
- `s7` ที่หายไปใน timeline (ข้ามจาก s6 ไป s8) เป็นของเดิมจากต้นฉบับ ไม่ใช่บั๊กที่ audit นี้สร้าง — ควรเติมหรือรีนัมเบอร์โดยเจ้าของยืนยันก่อน
